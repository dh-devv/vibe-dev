# 기술 결정 기록

결정마다 이유, 버린 대안, 감수하는 단점을 적는다. 외부 검토(심사위원, 보안, 구현·비용 관점)를 반영한 2차 판이다.

| # | 결정 | 이유 | 버린 대안 | 감수하는 단점 |
| --- | --- | --- | --- | --- |
| 1 | 주제는 "미루기 재판소" | 원인별 맞춤 처방을 공방으로 끌어내는 방식은 흔하지 않다 | 일정 플래너 | 가벼워 보일 수 있다. 지표와 안전 장치로 보완한다 |
| 2 | 판결은 사건마다 다른 처방 | 서비스의 다양성을 높인다 | "5분 행동" 고정 | 품질 편차. 검증기와 예시 사건으로 관리한다 |
| 3 | Python 3.12 | 설치되어 있고 두 SDK 모두 지원한다 | .NET, Node.js | |
| 4 | `GitHubCopilotAgent`로 연결 | 두 필수 기술을 한 경로에서 쓴다 | 모델 API 직접 호출 | 새 패키지라 자료가 적다. 실제 구현 전에 호출을 검증한다 |
| 5 | **재판 순서는 파이썬 코드가 제어** | 발언 순서가 고정이라 Agent Framework의 워크플로를 더해도 실익이 작고 일정 위험만 커진다 (구현·비용 검토) | Agent Framework 워크플로 | 오케스트레이션 시연이 약해 보일 수 있다. 에이전트 정의·도구·스트리밍·컨텍스트 전달로 보완한다 |
| 6 | 에이전트 3개 + 코드 검증기 | 활용 깊이가 중요하다. 검증은 코드가 더 정확하다 | 5개 에이전트 | 모델 기반 검토는 만들지 않는다 |
| 7 | 공방은 3발언 | 호출을 줄여 지연과 쿼터를 아낀다 | 5발언 | 공방이 짧다 |
| 8 | 도구는 함수, MCP는 P1 | 서비스가 하나 늘어 일정 위험이 크다 | 처음부터 MCP | MCP 시연이 빠질 수 있다 |
| 9 | **`azd` + Dockerfile, Aspire 제외** | 설치할 도구와 학습 시간을 줄인다. Aspire는 .NET 설치가 필요하고 Python 서비스 설정을 익혀야 한다 | Aspire, 전체 앱의 Compose 운영 배포 | Aspire의 통합 실행·추적 이점을 포기한다. Docker Compose는 로컬 DB 개발에만 쓴다 |
| 10 | 앱 1개(FastAPI API + React PWA) | 동일 출처 배포로 인증 쿠키와 API를 단순화한다 | API·UI 분리 배포 | 프런트엔드 별도 확장은 어렵다 |
| 11 | Azure PostgreSQL에 사용자 소유의 수용한 사건·판결·집행 기록을 저장 | 회원별 재판 이력 조회와 기기 간 접근에 필요하다. 공방 발언과 거부·오류한 결과는 보관하지 않는다 | 로컬 브라우저만 저장, 전체 대화 보관 | 민감한 사건 입력을 보관하므로 사용자별 권한, 삭제, 암호화, 백업 보존 고지가 필요하고 DB 비용이 든다 |
| 12 | React·TypeScript·Vite PWA | 타입 검사와 컴포넌트 구조로 인증·스트림·기록 상태를 관리하고 설치형 경험을 제공한다 | 정적 HTML/JS, 네이티브 앱 | Node 빌드와 PWA 캐시 보안 관리가 추가된다 |
| 13 | SSE 스트리밍 | 단방향이라 쉽고 공방을 실시간으로 보여 준다 | WebSocket | |
| 14 | 관리형 OAuth/OIDC 로그인, 사용자별 기록 권한 | 각 사용자의 기록을 분리하고 여러 기기에서 조회한다. 앱은 비밀번호를 보관하지 않는다 | 익명 사용, 자체 비밀번호 저장 | OIDC 공급자 선정·설정과 DB 운영 비용이 추가된다 |
| 15 | Container Apps 비밀로 토큰 주입 | 빠르고 코드에 비밀이 남지 않는다 | Key Vault | 회전·감사 기능이 약하다. 짧은 만료일로 보완한다 |
| 16 | **Application Insights 제외, 기본 Log Analytics만** | 비용과 운영 복잡도를 줄이고 사용자 내용이 로그에 섞일 위험을 낮춘다 | App Insights | 추적 화면이 약하다. 단계명·소요 시간 로그로 보완한다 |
| 17 | 위기 신호는 키워드 코드로 검사 | 빠르고 결정적이며 호출 비용이 없다 | 모델 분류 | 놓치는 표현이 있다. 면책 문구와 안내 번호를 함께 둔다 |
| 18 | **Copilot 도구를 `calc_deadline` 하나만 허용** | 런타임이 셸·파일 도구를 가질 수 있어 공개 서비스에서는 위험하다 (보안 검토) | 모두 승인 | 설정과 테스트 시간이 든다 |
| 19 | **초기 복제본은 최소 0, 최대 1** | 요청이 없을 때 비용을 줄이고 프로세스 메모리 기반 한도를 일관되게 적용한다 | 상시 1개 이상 또는 공유 저장소 없이 복제본 확장 | 첫 요청이 늦을 수 있다. 복제본을 늘리기 전에 공유 한도 저장소를 검토한다 |

## 초기 외부 검토 요약과 반영

| 지적 | 반영 |
| --- | --- |
| 문서 기준 4.1/10. 공개 URL·실동작 증거 없음 | PRD 11절에 URL 칸을 두고, 인수 조건을 배포 URL 기준으로 한다. **실제 점수는 배포와 동작 여부가 좌우한다** |
| 한도, 위기 안내, 길이 규칙 모호 | PRD 5~7절에 수치와 문구를 확정 |
| 셸·파일 도구 미차단 | TRD 3절, 결정 18 |
| XSS, 프록시 IP, 로그 혼입 | TRD 6절 |
| 호출 수 상충 | PRD 7절에 재시도 포함 최대 5회로 통일 |
| "CLI를 포함한다" 오류 | "CLI 런타임을 관리·다운로드한다"로 정정 |
| 사용자 인증 | 관리형 OAuth/OIDC를 사용하고 공급자 선정은 구현 전 완료 |
| 비용 | TRD 8절. 완전 무료는 보장하지 않음을 명시 |
| 회원별 기록·접근제어 | PRD 4·9절, API_SPEC.md, DATABASE.md에 인증과 소유권 검사 반영 |
