# TDD: 기술 결정 기록

각 결정의 이유와 대안, 감수하는 단점을 기록한다. (Technical Decision Document)

| # | 결정 | 이유 | 대안 | 감수하는 단점 |
| --- | --- | --- | --- | --- |
| 1 | 주제를 "미루기 재판소"로 한다 | 일정 플래너는 흔하다. 원인별 맞춤 처방을 적대적 공방으로 끌어내는 방식은 차별적이고, 멀티 에이전트의 필요성이 분명하다 | 일정 플래너 | 가벼워 보일 수 있다. 지표와 안전 장치로 보완한다 |
| 2 | 판결을 고정 처방이 아닌 맞춤 처방으로 한다 | 서비스의 다양성과 활용의 깊이를 높인다 | "5분 행동" 고정 | 품질 편차가 생긴다. 검증기와 테스트 사건으로 관리한다 |
| 3 | Python 3.12를 쓴다 | 이미 설치되어 있고, 두 SDK 모두 Python을 지원한다. 팀의 완성도를 기대하기 어려워 학습 비용이 낮아야 한다 | .NET(Aspire와 가장 자연스러움), Node.js | Aspire의 Python 지원은 .NET보다 자료가 적다 |
| 4 | 에이전트는 `GitHubCopilotAgent`로 연결한다 | 두 필수 기술을 하나의 경로로 쓴다. 평가 1항목(25%)의 핵심이다 | 모델 API 직접 호출 | 패키지가 새로워 문서가 적다. 단계 1에서 먼저 검증한다 |
| 5 | 에이전트를 3개와 코드 검증기로 시작한다 | 활용의 깊이가 에이전트 수보다 중요하다. 형식적 에이전트는 감점이다. 검증은 코드가 더 정확하고 빠르다 | 5개 에이전트 | 서기관의 모델 평가는 P1로 미룬다 |
| 6 | MCP 도구는 1개(마감 계산)만 둔다 | 검사의 주장 근거가 되어 판결 품질에 직접 쓰인다. 하루 안에 구현할 수 있다 | 도구 여러 개 | 도구 호출 시연이 단순하다 |
| 7 | 기록은 브라우저 `localStorage`에 저장한다 | 개인정보를 서버에 두지 않는다. DB 서비스가 필요 없어 배포가 단순하고 감점 위험이 없다 | Cosmos DB, Table Storage | 기기를 바꾸면 기록이 없다 |
| 8 | UI는 정적 HTML/CSS/JS로 한다 | 빌드 도구가 필요 없어 팀원 누구나 수정할 수 있다 | React, Blazor | 복잡한 상태 관리가 어렵다. 화면이 단순해 문제없다 |
| 9 | SSE로 스트리밍한다 | 공방을 실시간으로 보여 주어 지연을 체감하지 못하게 한다. 단방향이라 구현이 쉽다 | WebSocket | 양방향 통신이 안 된다. 필요하지 않다 |
| 10 | Azure Container Apps에 배포한다 | 규정이 허용하는 기본 도메인을 제공하고, 컨테이너 2개를 쉽게 운영한다 | App Service, Static Web Apps | 비용이 소액 발생한다 (정산 한도 내) |
| 11 | Aspire를 우선하고 `azd`를 대안으로 둔다 | Aspire는 한 번에 실행·추적·배포가 가능하고 Dockerfile이 필요 없다. 단 설치와 학습 시간이 든다 | Docker Compose | 13:30까지 성공하지 못하면 `azd`로 전환한다 |
| 12 | 로그인 없이 공개한다 | 심사 에이전트가 자격 증명 없이 써야 한다. 불가능하면 전 항목 1점이다 | 로그인 | 남용 위험이 있다. 요청 제한과 일일 상한으로 대응한다 |
| 13 | 서버 Copilot 인증은 토큰을 Key Vault에 두고 주입한다 | 코드에 비밀을 넣지 않는다. 평가 6항목(보안)과 3항목(안전한 클라우드 방식)에 부합한다 | 서버 간 토큰, BYOK | 정확한 권한과 쿼터는 미확인이다. 단계 0에서 확인한다 |
| 14 | 문서 순서를 AGENTS → PRD → TRD → TDD로 한다 | 방향을 먼저 고정해 AI가 추론하지 않게 한다. PRD·TRD는 제출 필수 문서다 | 코드부터 작성 | 문서 작성 시간이 든다 |

## 열린 질문

1. 서버에서 Copilot을 호출할 토큰의 종류와 필요한 권한, 공개 데모에서의 쿼터와 비용 부담
2. Aspire로 Python 서비스 2개를 Container Apps에 배포하는 구체적 절차
3. `agent-framework-github-copilot`에서 순차 워크플로와 스트리밍을 구성하는 방법

열린 질문은 해결되는 대로 해당 문서를 갱신한다.
