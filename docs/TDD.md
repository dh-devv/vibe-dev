# TDD: 기술 결정 기록

결정마다 이유, 버린 대안, 감수하는 단점을 적는다. 외부 검토(심사위원, 보안, 구현·비용 관점)를 반영한 2차 판이다.

| # | 결정 | 이유 | 버린 대안 | 감수하는 단점 |
| --- | --- | --- | --- | --- |
| 1 | 주제는 "미루기 재판소" | 원인별 맞춤 처방을 공방으로 끌어내는 방식은 흔하지 않다 | 일정 플래너 | 가벼워 보일 수 있다. 지표와 안전 장치로 보완한다 |
| 2 | 판결은 사건마다 다른 처방 | 서비스의 다양성을 높인다 | "5분 행동" 고정 | 품질 편차. 검증기와 예시 사건으로 관리한다 |
| 3 | Python 3.12 | 설치되어 있고 두 SDK 모두 지원한다 | .NET, Node.js | |
| 4 | `GitHubCopilotAgent`로 연결 | 두 필수 기술을 한 경로에서 쓴다 | 모델 API 직접 호출 | 새 패키지라 자료가 적다. 13:00에 먼저 검증한다 |
| 5 | **재판 순서는 파이썬 코드가 제어** | 발언 순서가 고정이라 Agent Framework의 워크플로를 더해도 실익이 작고 일정 위험만 커진다 (구현·비용 검토) | Agent Framework 워크플로 | 오케스트레이션 시연이 약해 보일 수 있다. 에이전트 정의·도구·스트리밍·컨텍스트 전달로 보완한다 |
| 6 | 에이전트 3개 + 코드 검증기 | 활용 깊이가 중요하다. 검증은 코드가 더 정확하다 | 5개 에이전트 | 모델 기반 검토는 만들지 않는다 |
| 7 | 공방은 3발언 | 호출을 줄여 지연과 쿼터를 아낀다 | 5발언 | 공방이 짧다 |
| 8 | 도구는 함수, MCP는 P1 | 서비스가 하나 늘어 일정 위험이 크다 | 처음부터 MCP | MCP 시연이 빠질 수 있다 |
| 9 | **`azd` + Dockerfile, Aspire 제외** | 설치할 도구와 학습 시간을 줄인다. Aspire는 .NET 설치가 필요하고 Python 서비스 설정을 익혀야 한다 | Aspire, Docker Compose | Aspire의 통합 실행·추적 이점을 포기한다 |
| 10 | 앱 1개(API + 정적 UI) | 리소스와 배포 단계를 줄이고 형식적 서비스 감점을 피한다 | API·UI 분리 | 확장성은 낮다 |
| 11 | 기록은 `localStorage` | 서버에 개인정보를 두지 않고 DB 비용이 없다 | Cosmos DB, Table Storage | 기기를 바꾸면 기록이 없다 |
| 12 | 정적 HTML/CSS/JS | 빌드가 없고 누구나 고칠 수 있다 | React | 복잡한 상태 관리는 어렵다 |
| 13 | SSE 스트리밍 | 단방향이라 쉽고 공방을 실시간으로 보여 준다 | WebSocket | |
| 14 | 로그인 없이 공개, 한도 적용 | 심사 에이전트가 자격 증명 없이 써야 한다 | 로그인 | 남용 위험. PRD 7절 한도와 복제본 1개로 대응한다 |
| 15 | Container Apps 비밀로 토큰 주입 | 빠르고 코드에 비밀이 남지 않는다 | Key Vault | 회전·감사 기능이 약하다. 짧은 만료일로 보완한다 |
| 16 | **Application Insights 제외, 기본 Log Analytics만** | 3시간·저비용 목표에 과하고 사용자 내용이 섞일 위험이 있다 | App Insights | 추적 화면이 약하다. 단계명·소요 시간 로그로 보완한다 |
| 17 | 위기 신호는 키워드 코드로 검사 | 빠르고 결정적이며 호출 비용이 없다 | 모델 분류 | 놓치는 표현이 있다. 면책 문구와 안내 번호를 함께 둔다 |
| 18 | **Copilot 도구를 `calc_deadline` 하나만 허용** | 런타임이 셸·파일 도구를 가질 수 있어 공개 서비스에서는 위험하다 (보안 검토) | 모두 승인 | 설정과 테스트 시간이 든다 |
| 19 | **복제본 최소 0, 최대 1** | 요청이 없으면 비용이 없고, 메모리 한도가 동작한다 | 상시 1개 이상 | 첫 요청이 느리다. 제출 전에 깨운다 |
