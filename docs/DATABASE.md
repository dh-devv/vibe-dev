# 데이터 명세
## 1. 저장 위치 한눈에 보기

| 데이터 | 위치 | 보관 기간 | 저장 시점 |
| --- | --- | --- | --- |
| 수용한 판결 기록 | 브라우저 `localStorage` | 사용자가 삭제할 때까지 | 사용자가 판결을 **수용**한 때 |
| 진행 중인 재판 (사건, 발언, 판결문) | 브라우저 JavaScript 변수 (메모리) | 탭을 닫거나 기각할 때까지 | 재판 중 |
| 한도 집계 (IP별, 전체) | 서버 프로세스 메모리 | 서버 재시작 전까지 | 요청마다 |
| 예시 사건 | 정적 파일 `web/samples.json` | 저장소에 포함 | 개발 시 |
| 사건 내용, 모델 출력 | **서버에 저장하지 않는다** | | |

Azure에는 데이터베이스, 스토리지, 캐시 리소스를 만들지 않는다.

## 2. 브라우저 저장소 (`localStorage`)

### 2.1 키

| 키 | 값 | 설명 |
| --- | --- | --- |
| `bao.v1.records` | JSON 배열 (`Record[]`) | 수용한 판결 기록. 최신 항목이 앞 |

키에 버전(`v1`)을 두어, 형식이 바뀌면 `v2`로 올리고 이전 값을 변환하거나 버린다.

### 2.2 `Record`

```json
{
  "id": "3f6c1c2e-8a53-4b5e-9d9a-1d2f7c0a9b11",
  "submittedAt": "2026-11-05T14:30:00Z",
  "acceptedAt": "2026-11-05T14:32:10Z",
  "caseText": "보고서를 3일째 못 쓰고 있다.",
  "deadline": "2026-11-07",
  "statements": [
    { "n": 1, "role": "defense", "text": "..." },
    { "n": 2, "role": "prosecution", "text": "..." },
    { "n": 3, "role": "defense", "text": "..." }
  ],
  "verdict": { "summary": "...", "cause": "막막함", "prescriptions": [], "evidence": [1, 2] },
  "checks": [[false, false], [false, false]],
  "firstCheckedAt": null,
  "completedAt": null
}
```

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `id` | string | `crypto.randomUUID()`로 만든 UUID |
| `submittedAt` | string | 사건을 접수한(재판 요청을 보낸) 시각 |
| `acceptedAt` | string | 사용자가 판결을 수용한 시각. 이 시각에 기록이 만들어진다 |
| `caseText` | string | 접수한 사건 내용 (5~300자) |
| `deadline` | string \| null | 마감일 |
| `statements` | array | 공방 발언 3개. `n`은 1~3, `role`은 `defense` 또는 `prosecution` |
| `verdict` | object | [API_SPEC.md](./API_SPEC.md) 4.5절 판결문 그대로 (위 예시의 `prescriptions`는 줄임) |
| `checks` | boolean[][] | 처방별 단계의 완료 여부. `checks[i][j]`는 `verdict.prescriptions[i].steps[j]`에 대응. 배열 크기는 판결문과 같아야 한다 |
| `firstCheckedAt` | string \| null | 처음으로 단계를 체크한 시각. 체크한 적이 없으면 `null` |
| `completedAt` | string \| null | 모든 단계를 체크한 시각. 하나라도 해제하면 `null`로 되돌린다 |

### 2.3 규칙

| 번호 | 규칙 |
| --- | --- |
| R1 | **수용한 판결만 저장한다.** 기각, 오류, 새로 고침 전의 재판은 저장하지 않는다 |
| R2 | 기록은 최대 50개다. 넘으면 가장 오래된 기록부터 지운다 |
| R3 | 읽을 때 JSON 파싱에 실패하거나 형식이 맞지 않으면 그 값을 무시하고 빈 배열로 시작한다. 화면이 멈추면 안 된다 |
| R4 | 저장에 실패하면(용량 초과, 저장 금지) 화면에 "기록을 저장하지 못했습니다"를 보여 주고 집행은 계속할 수 있게 한다 |
| R5 | 사용자는 "내 기록 모두 지우기" 버튼으로 `bao.v1.records`를 삭제할 수 있다. 삭제 전에 확인을 받는다 |
| R6 | 화면에 그릴 때 모든 문자열을 `textContent`로 넣는다. 저장된 값도 신뢰하지 않는다 |
| R7 | 토큰, 서버 내부 정보, IP는 저장하지 않는다 |

### 2.4 기록 화면 지표 계산

| 지표 | 계산 |
| --- | --- |
| 수용 건수 | `records.length` |
| 이행률 | `completedAt`이 있는 기록 수 ÷ 수용 건수 (건수가 0이면 "기록 없음") |
| 시작까지 걸린 시간 | `firstCheckedAt − submittedAt`의 평균 (`firstCheckedAt`이 있는 기록만, 없으면 "기록 없음") |

모든 계산은 브라우저에서 한다. 서버로 보내거나 집계하지 않는다.

## 3. 서버 메모리 (한도 집계)

서버는 사용자 데이터를 저장하지 않는다. 한도를 세기 위한 값만 프로세스 메모리에 둔다.

| 이름 | 구조 | 설명 |
| --- | --- | --- |
| `ip_minute` | `{ip: [요청 시각, ...]}` | 최근 60초 요청 시각. 오래된 값은 요청 때 지운다 |
| `ip_day` | `{(ip, UTC 날짜): 횟수}` | IP별 일일 횟수. 지난 날짜는 요청 때 지운다 |
| `global_day` | `{UTC 날짜: 횟수}` | 전체 일일 횟수 |

- 이 값은 재시작하면 사라진다. Container Apps 복제본을 **최대 1개**로 고정해 한도가 동작하게 한다.
- `ip_minute`와 `ip_day`는 항목 수를 10,000개로 제한하고, 넘으면 가장 오래된 항목부터 지운다 (메모리 보호).
- IP 문자열은 메모리에만 두고 로그에 남기지 않는다.

## 4. 정적 데이터

### 4.1 `web/samples.json`

심사자와 사용자가 입력 없이 재판을 시험하는 예시 사건이다. 서로 다른 원인이 드러나도록 3개를 둔다.

```json
[
  { "id": "report", "label": "3일째 못 쓴 보고서", "case": "...", "deadline": null },
  { "id": "exam", "label": "미뤄 둔 시험 공부", "case": "...", "deadline": null },
  { "id": "job", "label": "시작하지 못한 자기소개서", "case": "...", "deadline": null }
]
```

| 필드 | 규칙 |
| --- | --- |
| `id` | 영문 소문자, 고유 |
| `label` | 버튼에 보일 짧은 이름 (20자 이내) |
| `case` | 5~300자. 위기 신호 표현을 넣지 않는다 |
| `deadline` | `YYYY-MM-DD` 또는 `null`. 날짜가 지나면 거부되므로 `null`로 둔다 |

예시 사건 3개는 서로 다른 처방이 나오는지 인수 조건 3번으로 검증한다.

### 4.2 `src/app/safety.py`의 위기 신호 목록

자해·자살·극단적 선택을 뜻하는 한국어 표현 목록이다. 코드에 두고 단위 테스트로 검증한다. 이 목록은 사용자 데이터가 아니다.
띄어쓰기를 제거하고 소문자로 바꾼 뒤 비교한다. 놓치는 표현이 있을 수 있어 면책 문구를 항상 함께 보여 준다.

## 5. 환경 변수

| 이름 | 기본값 | 필수 | 설명 |
| --- | --- | --- | --- |
| `COPILOT_GITHUB_TOKEN` | 없음 | 예 | Copilot 호출용 토큰. 비밀 값. 저장소에 넣지 않는다 |
| `PORT` | `8000` | 아니오 | 서버 포트 |
| `LOG_LEVEL` | `INFO` | 아니오 | 로그 수준 |
| `IP_PER_MINUTE` | `3` | 아니오 | IP별 분당 한도 |
| `IP_PER_DAY` | `20` | 아니오 | IP별 일일 한도 |
| `GLOBAL_PER_DAY` | `300` | 아니오 | 전체 일일 한도 |
| `MODEL_TIMEOUT_SECONDS` | `30` | 아니오 | 모델 호출 1회 제한 시간 |
| `TRIAL_TIMEOUT_SECONDS` | `90` | 아니오 | 재판 1건 전체 제한 시간 |

예시는 [.env.example](../.env.example)에 있다. 로컬에서는 `.env`를 만들어 쓰고, 배포에서는 Container Apps 비밀과 환경 변수로 넣는다.
